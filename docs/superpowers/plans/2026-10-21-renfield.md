# renfield Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `renfield`, a single-binary Rust tool that lets a source machine run commands, edit files and move files on a dest machine over mutually authenticated TLS 1.3, with an MCP server mode for Claude Code.

**Architecture:** One binary, subcommands for both roles. Dest listens on TLS 1.3 with a self signed Ed25519 certificate; peers are authenticated by pinned SHA-256 fingerprint of the certificate DER (no CA, no hostname checks). After the handshake, peers exchange length prefixed frames (JSON control messages, raw binary data frames). Pairing is a two phase exchange (offer, then commit or abort) on the same port while dest is in `--accept-key` mode.

**Tech Stack:** Rust stable, `tokio`, `tokio-rustls` + `rustls` (ring provider, TLS 1.3 only), `rcgen`, `clap`, `serde`, `serde_json`, `toml`, `sha2`, `hex`, `anyhow`/`thiserror`, a hand written JSON-RPC MCP stdio server (no heavy MCP crate).

**Spec:** `docs/superpowers/specs/2026-10-21-renfield-design.md`

## Global Constraints

- Single executable, zero runtime dependencies, no OpenSSL; Windows with static CRT; Linux release verified on the `x86_64-unknown-linux-musl` target.
- TLS 1.3 only, mutual auth, self signed certs, peer verified by pinned fingerprint (not CA, not hostname).
- Non interactive only: no PTY, no stdin attached to commands.
- Pairing is one way unless `--both`; the human confirms on dest (mandatory) and on source; reject or abort on either side stores nothing on either side.
- Dest is unrestricted (permissions of the OS user only).
- Code and comments in English, no em dash anywhere; doc comment on every function; exit conditions at the top as one liners where possible; constants UPPER_CASE; text files end with an empty line; `CHANGES.md` updated per feature; one commit per completed and tested feature, never `--no-verify`, no AI attribution lines in commit messages, never push.
- Config dir: `~/.config/renfield/` (Linux/macOS), `%APPDATA%\renfield\` (Windows); overridable with the `RENFIELD_HOME` env var (tests rely on it). Private key readable by owner only. Registry and authorized keys are TOML.
- Defaults: pairing window 120 s; MCP exec timeout 120 s, CLI no timeout; stdout and stderr capped at 1 MiB each in MCP mode (tail kept, `truncated` flag); `remote_read` cap 1 MiB; Windows default shell Windows PowerShell 5.1, Linux `bash` else `sh`; relative paths resolve against the home dir of the dest user, `~` expanded.

## Review Focus

1. Dest key changed since pairing: source fails with a clear "key mismatch for <name>, re-pair" message, never connects.
2. Unpaired source connects to normal dest: clear "not authorized on <name>, run pair first" (TLS 1.3 reports the rejected client cert only on the first read; map it).
3. Pairing with a name already in the registry: refused unless `--force`.
4. Edit on a CRLF file with an LF `old_string` still matches and keeps CRLF endings.
5. Command with no output, huge output, or non UTF-8 bytes: exit code still returned, no panic, lossy conversion noted.
6. Connection dropped mid exec or mid transfer: clear error naming the machine, partial target file never left behind.
7. Paths with spaces, unicode and Windows backslashes on `put`/`get`/`remote_*`.

## File structure

```
Cargo.toml
src/main.rs        entry point, clap dispatch, exit code mapping
src/cli.rs         clap definitions
src/error.rs       RenfieldError + exit code constants
src/home.rs        config dir resolution, file paths, 0600 perms
src/identity.rs    load or create cert+key, fingerprint
src/store.rs       Registry, Authorized (TOML load/save)
src/tls.rs         pinned verifiers, client/server TLS configs
src/proto.rs       Frame codec, Request, Response, ShellKind
src/server.rs      listen loop, per connection dispatch, audit log
src/exec.rs        shell spawn, streaming, timeout, tree kill
src/files.rs       read, write, edit, list operations (pure, local fs)
src/transfer.rs    put/get chunk streaming + sha256 (both ends)
src/pairing.rs     two phase pairing, source and dest sides
src/client.rs      connect(name) + typed calls used by CLI and MCP
src/mcp.rs         MCP stdio server and tool definitions
tests/             integration tests on loopback (one file per task)
```
